# FE Bar Submission Guide

## Customer problem

Influencer-marketing leaders cannot quickly connect new creator and campaign activity to attributed revenue, campaign ROI, and renewal risk. Data is fragmented across CRM, marketing, social, contract, and billing systems; operational portals lag the analytical lakehouse; and analysts must manually interpret campaign performance.

This prototype gives a marketing leader one governed journey from synthetic source events to operational APIs, persisted GenAI recommendations, and natural-language analysis.

## Quantified outcome

For an illustrative global consumer brand spending $10M annually on influencer marketing, redirecting 2% of inefficient investment protects $200K per year. The live demo measured 4 minutes 22 seconds from raw synthetic event to confirmed API response, replacing a next-day manual handoff assumption. These values are explicitly illustrative and require production calibration.

## Build approach and AI collaboration

The build used an AI coding agent as a teammate for rubric gap analysis, implementation, Databricks deployment, runtime diagnosis, evidence capture, and roleplay preparation. The working prompt required a specific influencer-marketing outcome, an integrated platform journey, real deployment, and readable execution evidence rather than architecture-only claims.

## Required-stage mapping

| Requirement | Implemented artifact | Runtime evidence |
|---|---|---|
| Lakeflow | Four-layer serverless SDP in `src/pipeline/01_bronze.sql` through `04_platinum.sql` | `evidence/orchestration_run.md` |
| Unity Catalog | Managed schema, volumes, tables, comments, constraints, metric views, and app grants in `databricks.yml` | `evidence/governance_and_data.md` |
| Lakebase | Triggered synced tables for brand, campaign, and creator operational serving | `evidence/lakebase_and_api.md` |
| ML or GenAI | `ai_gen` persists grounded actions; the live model route is traced by MLflow into UC | `AI_GEN_RECOMMENDATIONS.sql`, `MODEL_ENDPOINT_RECOMMENDATION.py`, `RAW_EXECUTION_TRANSCRIPT.md` |
| Genie Agent | Curated Traackr agent over performance, renewal, AI, and API-reference data | `evidence/genie_agent.md` |
| Databricks App | FastAPI developer portal, business recommendations, API playground, architecture, and latency demo | `evidence/lakebase_and_api.md` |

## Integrated journey

`synthetic raw files → UC Volume → Bronze streaming tables → Silver/Gold materialized views → Platinum serving tables → GenAI enrichment → Lakebase synced tables → FastAPI/Databricks App → Genie Agent`

The day-2 job encodes the dependency chain. GenAI runs only after Lakeflow succeeds. Lakebase refresh runs only after both Lakeflow and GenAI succeed. The freshness check runs only after Lakebase refresh.
